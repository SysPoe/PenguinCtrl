Executive verdict

Not ready for show-critical deployment

The application is a promising functional prototype, but its present failure semantics are unsafe for a heavy theatrical environment. A cue can be accepted by the engine while the corresponding output event is silently discarded; pause and seek do not reschedule the engine's end timer; audio is tied to an output window and uses blocking work in a real-time callback; output-window loss creates ghost playback; and many runtime errors never reach the operator. These are deterministic defects in current code paths, not merely missing enterprise polish.

Use it only in rehearsal, non-critical playback, or with an independent, instantly available fallback until the critical items in this report are fixed and fault-injection tests pass.

What is already good

  • The app is local and native; it does not depend on a browser or localhost service.
  • Show snapshots and many core structures are protected by locks, show saves attempt a temporary-file replacement, and archive extraction includes a path traversal check.
  • Playback has explicit cancellation contexts, separate preview routing, cue warnings, a focus-loss warning, an audio-device warning, and black idle output windows.
  • Targeted non-UI tests and the race detector passed during this audit. The limitation is coverage: the most failure-sensitive behaviours are not tested.

Runtime architecture and failure domains

One process owns the operator window, every output window, cue scheduling, show mutation, explicit archive packaging, FFmpeg child processes, audio devices, and remote-control transmission. A failure or resource stall in any of these paths can therefore affect all show functions.

Critical findings — fix before show-critical use

R-01 CompletePlayback and control delivery reconciles from authoritative state

Impact: a GO, STOP, fade, seek, blackout, or remove can exist in engine state but never reach the output window. The operator may see a cue as active while nothing plays, or press STOP while output continues.

Evidence: playback/events.go:105-113 uses a non-blocking send with an empty default; subscriber buffers are only 32 events. media/manager.go:181-198 adds another bounded handoff. There is no sequence number, acknowledgment, retry, or reconciliation after a dropped incremental event.

Recommendation: replace the lossy fan-out with a per-output state machine and reliable command mailbox. Give every mutation a monotonic sequence number; require the output to acknowledge application; on a gap, send a complete authoritative snapshot. STOP/blackout must use a reserved, non-droppable priority path. Add queue-depth, gap, and apply-latency telemetry. Test with a deliberately frozen output event loop.

Completed: output events carry monotonic sequence numbers, overload collapses to a mandatory resync marker, and both resync and new subscriptions apply a complete authoritative engine snapshot before later increments. STOP and blackout therefore cannot remain silently lost behind an overloaded incremental queue.

R-02 CompletePause and seek replace lifecycle timers

Impact: paused media still reaches its originally scheduled logical end; seeking backward can end early and seeking forward can end late. End links may fire while media is paused or at the wrong point in the file.

Evidence: playback/engine.go:566-600 schedules one wall-time end goroutine and sets EndScheduled. playback/engine.go:632-667 updates position/paused flags but neither cancels nor recreates that timer. The player restarts on seek/resume in media/player.go:276-325, while engine timing remains unchanged.

Recommendation: give each instance a lifecycle generation/cancel function. Pause cancels its fade/end timers; resume and seek materialise position and schedule fresh timers from remaining media time. Ignore reports from stale generations. Use one injectable monotonic clock and build deterministic tests for pause-before-fade, long pause, forward/back seek, repeated seek, and Stop All races.

Completed: lifecycle work is generation-based; pause invalidates pending completion, and resume or seek materialises the position and schedules from the new remaining duration. Deterministic tests cover stale pause and backward-seek timers.

R-03 CompleteAudio uses long-lived endpoint mixers and non-blocking callbacks

Impact: FFmpeg scheduling, pipe stalls, garbage collection, or a slow disk can block the hardware callback and cause clicks, dropouts, or device hangs. Concurrent cues can exhaust or contend for Windows audio endpoints. Audio also disappears when its owning output window closes.

Evidence: media/audio.go:116-127 calls io.ReadFull directly inside the malgo data callback. media/audio.go:61-105 initialises and starts a new device for every player. Players are stored and closed by outputWindow in media/manager.go:148-209.

Recommendation: build one long-lived mixer per physical device. Decode into bounded lock-free or carefully synchronised ring buffers on worker goroutines; the real-time callback must only copy ready samples, apply precomputed gain, and zero-fill on underrun. Keep audio independent of visual windows. Expose underrun counts, callback timing, buffer occupancy, sample clock, and endpoint state.

Completed: playback and preview routes reuse one long-lived mixer per selected physical endpoint. Decoder workers fill bounded SPSC rings; the endpoint callback reads immutable source snapshots without locks, I/O, or allocation, sums with saturating gain, and zero-fills missing samples. Mixer metrics expose active source count, per-source underruns, last/max callback timing, endpoint recovery state, and recovery count. Mixer lifetime is application-owned rather than output-window-owned.

R-04 CompleteAudio routes have explicit loss, retry, and continuity policy

Impact: unplugging a selected endpoint makes new cues fail; an already-open device has no reconnection path. Video can continue silently because its audio-start error is intentionally ignored. Replugging does not rebind active streams.

Evidence: media/manager.go:50-98 creates a warning by polling enumeration. media/audio.go:75-90 rejects a missing selected ID. media/player.go:163-167 returns audio startup errors only for audio-only media, discarding them for video. There is no device notification, mixer restart, fallback, or recovery state.

Recommendation: use Windows endpoint notifications where available, with a short polling fallback. Define explicit per-route policy: fail closed, switch to named backup, or follow system default. On loss, immediately show a latched red alarm and audible/operator alert, freeze unsafe GO actions if configured, reopen the mixer with bounded exponential retry, and either resume from the shared media clock or require a confirmed operator action. Never hide video-audio failure.

Completed: endpoint loss and video-audio startup failures produce a latched persistent operator alarm and preflight blocker. Playback and preview independently configure fail-closed, follow-Windows-default, or named-backup policy. A stopped mixer attempts six bounded exponential primary reopens, then recovery kills the stale decoder generation, starts FFmpeg at the instance's current shared-clock position, prebuffers a replacement source on the declared fallback, atomically swaps the session, and suppresses the expected old-decoder exit. Exhausted fail-closed or fallback recovery marks the route failed and terminates affected sessions as unexpected.

R-05 CompleteDesired output windows recover from loss

Impact: Windows, a monitor hotplug, the operator, or a Gio error can close an output. Its players stop, but the engine retains live instances; waits and control cues then reason about media that is not actually playing. The output is removed and normally remains absent.

Evidence: media/manager.go:169-209 closes players with report=false on DestroyEvent and removes the window. Reopen occurs only when the explicit reopening flag is set. SyncOutputs is event-driven, not a health supervisor.

Recommendation: distinguish intentional operator close from crash/device/display loss. In show mode, prevent accidental close or immediately recreate the assigned output with backoff. On loss, reconcile every player with engine state: either resume at current monotonic position or atomically mark instances failed/stopped and block dependent links. Add heartbeat and generation IDs so stale windows cannot report against replacements.

Completed: the manager now distinguishes removed outputs from still-desired outputs, suppresses recovery during controlled shutdown, and recreates an unexpectedly closed desired window with backoff. Every replacement subscribes through an ordered authoritative snapshot containing materialised current positions, so ghost engine instances reconcile into the new generation.

R-06 CompleteFailures are visible and attributable

Impact: remote cues, media control, output startup, and playback errors can fail without a persistent operator alarm. A UDP write can succeed when no console is listening. The operator cannot reliably distinguish “command accepted” from “effect confirmed.”

Evidence: playback/engine.go:1057-1070 stores only the last error; no UI reads LastError. Output event handling at media/manager.go:297-321 has no error case. Sidebar controls discard returned errors. Player startup errors are only logged at media/manager.go:337-341.

Recommendation: add a latched incident panel with timestamp, cue number/name, output/device/target, phase, severity, acknowledgment, and recovery action. A cue row must show queued, applied, confirmed, failed, or degraded. Keep bounded error history in memory and rotating disk logs. Treat “no target matched” as an operator-visible warning for control cues. Remote health must be separate from socket-write success.

Completed 13 July 2026: the operator surface, cue-row failure state, bounded/rotating history, no-target result, direct/automatic GO policy, and sent/unconfirmed UDP semantics are implemented. Protocol-level remote acknowledgement remains tracked under R-15 rather than being misrepresented as part of UI success.

R-07 CompleteShow edits and application exit are crash-safe

Impact: closing, crashing, starting a new show, or opening another show can lose recent work. A queued autosave is not flushed on shutdown. Save As can leave a partial user-selected file. Autosave replacement has a Windows/OneDrive-sensitive gap.

Evidence: main.go:520-559 debounces autosave in an unmanaged goroutine; main.go:574-577 closes playback and returns without draining it. New/Open paths do not require dirty confirmation. Save As writes directly through the explorer handle at main.go:453-487. Replacement at main.go:733-748 temporarily moves the old file aside and ignores several cleanup/restore errors.

Recommendation: maintain a small write-ahead edit journal independent of the portable media archive. On every mutation, append and flush a versioned record; periodically checkpoint a compact show snapshot. On startup, offer verified recovery. Track dirty state and require Save/Discard/Cancel for New, Open, and Close. Save As to a sibling temporary file, fsync, validate by reopening, then replace. Retain timestamped recovery generations rather than one fixed backup.

Completed: every changed show generation is appended to a bounded, versioned JSONL journal and fsynced independently of media packaging; torn final writes are ignored; records are digest-validated; startup restores the latest dirty generation; successful save/load writes a clean generation; normal close flushes dirty state; and Save As uses sibling-temp publication. Dirty New, Open, and native Windows Close actions now pause behind an explicit Save/Discard/Cancel modal, with failed or cancelled saves retaining the current show.

High-priority findings

R-08 CompleteCue actions cross a deterministic command sequencer

Every accepted command receives a monotonic sequence while enqueueing. Independent pre-waits may run concurrently, but cue actions cross the sequence gate in acceptance order; cancelled generations explicitly release their sequence so they cannot stall later work. Wait actions release the gate when the wait begins, while media decoding remains the declared parallel boundary. A bounded command audit records sequence, cue, origin, accepted time, dispatch time, and completion time.

R-09 CompleteImminent media is validated and pre-rolled

Asynchronous readiness checks and blocker enforcement validate sources before GO. The selected cue and following playable media cues now enter a bounded pre-roll cache: FFmpeg probes and decoders start, video supplies its first timestamped frame, audio fills its ring buffer without joining the live mixer, and GO atomically claims the ready session. Cache entries include route, clip position, FFmpeg, and stage-resolution identity; stale entries are LRU-closed, failed warming is backstopped, and all warming is cancelled during manager shutdown.

R-10 CompleteExternal media processes have lifetime supervision

Playback decoders, audio recovery decoders, probes, waveform extraction, and archive transcoding all launch through one supervised process boundary. On Windows, each child is assigned immediately to an application Job Object configured with KILL_ON_JOB_CLOSE, so FFmpeg, FFprobe, and their descendants are terminated when the app process dies. Context deadlines and session cancellation still provide per-task shutdown; assignment failure kills the new child and fails closed rather than leaving an orphan.

R-11 CompleteAudio and video share a presentation timeline

Each decoded video frame carries a presentation timestamp and each active audio route counts rendered sample frames. When audio exists, the shared playback clock rebases onto that monotonic sample position; video-only media uses the monotonic wall clock. Video selects the newest due frame, drops stale frames, repeats the current frame when the decoder is early, and reports absolute A/V drift in session metrics. Pause, seek, restart, and device recovery rebase the same clock, and an eight-hour simulated master-clock test verifies that wall-clock scheduling cannot accumulate lip-sync drift.

R-12 CompleteDecoder work has global admission and memory bounds

The shared backend admits at most twelve concurrent decoder sessions and reserves estimated RGBA queue memory against a 512 MiB global budget before launching FFmpeg. Dimension, pixel-count, frame-rate, video-bitrate, and aggregate audio-bitrate limits are enforced before allocation. Video frames use a per-session pool and bounded backpressure. Output compositing suspends fully obscured or blacked-out video decoders while their logical presentation time continues, then restarts them at the current clock position when revealed.

R-13 CompleteRoutine recovery never packages the portable archive

Every show mutation is synchronously appended and flushed to the bounded recovery journal, which contains only show state. The former debounce worker and automatic project.Save archive rebuild have been removed. Media hashing, transcoding, ZIP writing, and atomic archive publication now run only for an explicit Save or Save As action under the save mutex, so playback cannot unexpectedly trigger packaging I/O.

R-14 CompleteSettings updates are transactional and recoverable

A candidate is encoded and flushed before publication, the previous primary is retained as a last-known-good generation during Windows replacement, failed publication leaves the in-memory snapshot unchanged, startup restores an interrupted replacement, and corrupt primaries are preserved before falling back to the verified backup. Failure, replacement, recovery, and corrupt-primary tests cover the boundary.

R-15 CompleteRemote delivery has explicit assurance and redundancy policy

Remote targets execute concurrently with a 750 ms command deadline and an operator-configurable “all targets” or “any redundant target” success policy. Plain console UDP remains correctly labelled sent/unconfirmed and is never blindly retried. Targets can declare a TCP health port for continuous bounded reachability probes, plus an acknowledgement-relay port that receives a base64 command envelope with an idempotent command ID; only an exact matching ACK succeeds, and safe retries reuse that ID. Per-target health records reachability, acknowledgement, round trip, last success/error, and consecutive failures.

R-16 CompleteProcess failure is captured and supervised into a safe restart

The application now returns through one coordinator: initialization and window errors are logged, runtime cleanup completes inside runMain, and only the outermost main function publishes its final exit code. Top-level panics produce bounded, fsynced stack reports; Go runtime crash output also captures unrecovered panics and fatal throws from any goroutine. The separate cusus-supervisor executable owns the app in a kill-on-close process job and restarts abnormal exits with bounded exponential backoff. Restart reconstructs the show document but never reconstructs playback instances, audio, or remote execution, so recovery is black, silent, and requires explicit operator GO.

R-17 CompleteWindows output assignment and kiosk policy are durable

Each stage persists the Windows display-interface identity, display-relative geometry, fullscreen state, output resolution/scaling, expected refresh rate, always-on-top policy, locked-fullscreen policy, cursor policy, and operator confirmation. Enumeration reports physical dimensions, refresh, and effective DPI in Settings. A topology monitor detects disconnect, reconnect, resolution, refresh, or DPI changes, reroutes a missing assignment to the primary display with a prominent warning, and reapplies the saved route when hardware returns. Locked outputs ignore accidental double-click exit; test grid, safe-area overlay, identify message, and explicit confirmation provide the pre-show mapping check.

R-18 CompletePower and clock discontinuities fail safe

A Windows execution-state keeper requests system and display availability for the lifetime of the operator window and clears the request during controlled shutdown. The frame heartbeat detects resume or scheduler stalls over three seconds. Detection atomically latches GO, cancels every cue generation and lifecycle timer, stops all live output instances, records a show-stopping event, and presents a persistent red interruption banner. No manual, linked, or embedded cue can start until the operator explicitly selects “Acknowledge and re-arm GO”; re-arming never resumes prior sound, video, or remote actions.

R-19 CompleteGO is gated by a signed full-integrity preflight

A lifecycle-owned background service computes preflight outside the Gio frame path and signs the check set against both the complete show digest and the current settings/device/remote-health environment. A stale, computing, tampered, or critically failing result blocks every manual, linked, and embedded GO. Checks cover cue structure and timing, duplicate identity, resolved targets, asynchronous media decodability/duration, FFmpeg/FFprobe capability, audio and display routes, display confirmation/refresh, remote active health, cache writability, free space, and a two-copy media packaging forecast. Cautions retain the existing per-show fingerprint acknowledgement and audit trail; critical failures cannot be acknowledged away.

R-20 CompleteArchive assets are verified before publication

Loading now rejects duplicate or undeclared entries, missing cue assets, unsafe paths, unsupported kind/format pairs, size mismatches, SHA-256 mismatches, excessive entry/asset/total sizes, and excessive expansion ratios. ZIP CRC is verified by the archive reader. Extraction is flushed into a temporary sibling directory and only published after the complete archive validates. New archives record a packaged-content hash; legacy version-1 archives without that added field remain readable while still receiving size, CRC, path, format, and completeness validation.

R-21 CompleteShow read APIs no longer expose mutable internal state

GetCue, GetCueByID, SelectedCue, Cues, Snapshot, and the copy helpers now return recursive cue copies while mutation remains behind manager methods that hold the lock and emit change notification.

R-22 CompleteFilesystem and device probes are outside the UI event loop

Cue media validation, duration work, signed preflight, executable checks, disk forecasting, audio endpoint enumeration, and Windows display enumeration all run in lifecycle-owned background workers. Gio layout reads only versioned cached results. Audio/display refresh buttons signal the workers rather than calling device APIs synchronously; periodic probes are cancellable with manager shutdown. A missing OneDrive path or stalled device API can no longer block keyboard dispatch or GO handling in the frame loop.

R-23 CompleteCache growth and free-space reserve are enforced

Extracted shows remain content-addressed by archive hash and transcodes by source hash; every hit updates its LRU timestamp. A lifecycle-owned maintainer runs only while no cue or synchronous execution is active, inventories show-cache objects and transcodes, protects every path referenced by the current show, and evicts oldest unreferenced objects until both the operator-configurable quota and reserved-free-space threshold are satisfied. Settings expose quota and reserve in GiB. The signed preflight independently blocks GO when its two-copy packaging/cache forecast exceeds current free space.

R-24 CompleteFault boundaries have deterministic, Windows, race, and soak evidence

The reliability matrix maps output saturation, lifecycle timers, decoder failures and limits, archive corruption, settings replacement/rollback, rapid ordering, output recovery, device loss policy, cache pressure, crash reporting, and process containment to regression tests. CI runs the full deterministic suite, vet, and build on both supported Windows runner generations and the full race suite on Linux. A versioned PowerShell evidence runner records commit, machine, Go version, step logs, and results; its optional real-media multi-hour soak repeatedly cycles overlapping decoders/devices and is the required release-candidate hardware evidence path.

Medium-priority hardening

R-25 CompleteOperational logs and redacted support bundles are available

Operator and console diagnostics are written as structured JSONL with nanosecond timestamps, monotonic event sequence, session/build/show identity, cue identity, source, severity, and optional telemetry details. Logs rotate through four bounded generations while the in-app incident surface retains its bounded view. Settings now provides one-click support-bundle export containing a manifest, current-session events, bounded rotated logs, recent crash reports, and recursively redacted configuration; publication is temporary-file-first and atomic.

R-26 CompleteBackground work has bounded lifecycle ownership

A reusable application task group now owns file pickers, open/save work, waveform decoding, and every UI completion callback with cancellation, a four-task concurrency bound, tracked joins, and a shutdown deadline. UI delivery selects on the application context, so a full channel or closed window cannot strand a sender. The playback engine tracks and joins duration/validation probes, cue execution, links, timecode markers, lifecycle timers, transitions, and fades after cancellation. Each media player similarly owns and cancels restart, preload, duration, fade, and session-report workers; close joins them, and FFmpeg waveform/duration operations inherit the owning context. Existing preflight, cache, remote, output/device monitor, decoder component, and audio workers retain their dedicated cancellation/close ownership.

R-27 CompleteOutput composition has deterministic layers and resource behaviour

Each output uses its configured layer count, with command sequence as the primary back-to-front order and start time plus instance ID as deterministic legacy tie-breaks. The existing transition state owns blackout/fade ordering, visual opacity follows the same programmed gain curve used by audio, and decoders outside the visible layer set are suspended without stopping their logical clocks. Equal-time ordering has a dedicated regression test.

R-28 CompleteProgrammed gain has explicit supported semantics

Positive values now apply real linear gain up to +12 dB, with saturating sample conversion rather than integer wraparound. Static cue and media-control preflight blocks non-finite values and values above the implemented headroom, so the runtime no longer silently reports a level it cannot reproduce.

R-29 CompleteEmergency controls remain reachable on fallback displays

The operator window now restores and persists Win32 position/size, starts at the saved geometry, and can shrink to 480×320 instead of enforcing 1300×720. Below 850 px the cue list uses the full content width; below 900 px nonessential top-bar actions collapse. STOP ALL and BLACKOUT remain the first fixed controls at every width, work on Settings and modal/focused states, and have global F12 and Ctrl+Shift+B shortcuts. BLACKOUT writes authoritative state and immediately publishes to every configured/active output. Fullscreen no longer toggles on double-click: it is changed only by explicit output-control cues/settings, and the per-output lock prevents accidental exit.

R-30 CompleteWindows releases are reproducible, identified, signed, and auditable

Commit-pinned CI actions run the supported Windows matrix, race suite, vet/build tests, and pinned govulncheck. The release workflow accepts only versioned clean commits with matching reliability evidence, injects version/commit/UTC commit time plus config/show schema constants, embeds Win32 DPI/long-path/requested-execution manifests and version resources in both executables, and requires Authenticode signing plus verification for published artifacts. Packaging normalises timestamps and trim paths, clears the linker build ID, emits deterministic zip bytes, SHA-256 hashes, SPDX 2.3 SBOM, release manifest, installer, and operator notes. CI exercises install, in-place upgrade, and rollback before publishing immutable tagged assets.

R-31 CompleteShow schema evolution is explicit and migration-safe

The archive schema is now version 2 with explicit lower-camel JSON names for every persisted CuSus field, deterministic defaults and stable IDs, bounded structural validation, a registered stepwise migration from version 1, and clear rejection/update guidance for future versions. Unknown members in a supported version are ignored by policy; namespaced show.extensions values are raw-JSON-preserved through manager copies and subsequent saves. Golden manifests cover every released version, migration/round-trip tests enforce current encoding and extension retention, and an archive immutability test proves loading/migration never rewrites the source or only copy.

R-32 CompleteUnified component health is typed, visible, and actionable

A lifecycle-owned background health service publishes one sorted snapshot for the playback engine, show archive/checkpoint, every audio endpoint, display mapping, active decoder, cache volume, and remote target using Normal, Degraded, Recovering, or Failed states. Endpoint identity, affected cue numbers, last successful callback, recovery count/progress, underruns, display IDs, decoder state/latency, disk reserve, archive dirtiness, and remote acknowledgement/round trip are retained as structured details. Overall health remains visible in the top bar; every non-normal component becomes an operator preflight item with state, consequence, and a specific recovery action, while filesystem/device collection remains off the Gio frame loop.

R-33 MediumNo external timecode or deterministic timeline strategy

For complex theatre integration, independent local timers are insufficient for synchronising departments and recovering from jumps. If the product scope includes timed sequences, define support for a master monotonic timeline and optional LTC/MTC/OSC timecode, including chase, discontinuity, hold, and resync policies. Keep manual cue stacks independent where external timecode is inappropriate.

R-34 MediumNo redundancy or rehearsed fallback handoff

The app is a single control and playback node. For heavy productions, specify a warm spare with prevalidated identical show/media, audio/display mappings, and a safe manual or heartbeat-gated takeover method. Do not allow both nodes to issue remote GO simultaneously. Rehearse transfer, split-brain prevention, and return-to-primary.

Recommended target architecture

  1. Deterministic show coordinator: one ordered command log, one injectable monotonic clock, explicit state transitions, generation IDs, and a priority emergency-control lane.
  2. Reliable output agents: each output applies sequenced desired state, acknowledges it, detects gaps, and can be restarted/reconciled independently. A separate process is preferable for fault isolation.
  3. Central audio engine: one mixer per endpoint, pre-opened devices, decoder workers feeding bounded ring buffers, meters/underrun telemetry, and policy-driven endpoint failover.
  4. Timestamped media pipeline: shared demux/clock for audio and video, pooled buffers, bounded decode resources, preload, and explicit end/error distinction.
  5. Durable document service: write-ahead edit journal plus small checkpoints; portable archive packaging is an explicit background/export operation, not routine autosave.
  6. Health and incident service: a unified state model, structured rotating logs, operator alarms, build/show/session IDs, and support bundle export.
  7. External supervisor: owns process restart and crash collection and always restarts outputs black/silent. A warm spare handles machine-level failure.

Reliability test programme

Deterministic automated tests

  • Fake clock tests for pre-wait, post-wait, pause/resume, seeks, fade overlap, Stop All, timecode markers, link suppression on failure, and suspend-sized clock jumps.
  • Reliable bus tests with slow/dead subscribers, queue saturation, sequence gaps, output restart, duplicate/stale acknowledgment, and priority STOP/blackout.
  • Settings tests for Windows replacement failure, disk full, read-only directory, corrupt JSON, orphan temp/backup recovery, and in-memory rollback.
  • Archive tests for truncation, missing/duplicate assets, wrong checksum/size, zip bomb limits, unsafe paths, interrupted extraction, old-version migration, and round-trip golden files.
  • Decoder tests for missing FFmpeg, startup timeout, corrupt streams, early exit, huge dimensions, no audio stream, no video stream, variable frame rate, and stale process reports.
  • Remote tests for deadline, target isolation, protocol payloads, retry/deduplication policy, unavailable DNS, and partial multi-target success.

Suggested measurable budgets

  • Zero lost control events and zero unacknowledged state gaps in a 24-hour stress run.
  • STOP/blackout dispatch p99 under 20 ms inside the application at supported maximum load.
  • Preloaded audio onset p99 under an agreed production threshold (typically 20–50 ms), measured at physical output.
  • No real-time audio callback blocking, allocations, or locks; zero underruns in the supported load matrix.
  • A/V sync remains within the agreed threshold (for example ±20 ms) for the longest supported clip.
  • Output/device-loss alarm within one second; recovery or declared failure within a bounded, documented time.
  • Crash recovery loses no acknowledged edit and never auto-fires a cue.

Windows and show-day hardening

Operational controls cannot repair software defects, but they reduce environmental variance after the critical code work is complete.

Machine build

  • Use a dedicated, tested Windows image and local administrator-controlled update window; disable automatic restart during performances.
  • Use High/Ultimate Performance power settings; disable sleep, hibernate, USB selective suspend, display sleep, and NIC power saving while in show mode.
  • Keep show and cache files on a local SSD. Package/synchronise through OneDrive outside show mode; do not play directly from a cloud placeholder.
  • Pin and document GPU, audio-interface, chipset, and network driver versions. Disable enhancements/spatial audio and select a fixed supported sample rate.
  • Exclude the signed application and local media/cache directories from real-time scanning only under the organisation's approved security process; validate the exact configuration.
  • Disable notifications, Focus Assist interruptions, screen savers, hotkeys/overlays, and unrelated startup/background applications.
  • Use cabled network for remote control, a dedicated switch/VLAN where appropriate, static addressing, and UPS power for the PC, displays, interface, and network.

Pre-show checklist

  1. Boot from cold; verify app/build hash and open the local packaged show copy.
  2. Run full preflight: archive hashes, media decode, device routes, sample rate, displays, remote targets, disk space, cache, and clock.
  3. Show test pattern/identify on every physical output and require operator confirmation of mapping/fullscreen.
  4. Play a test tone through every playback and preview route; verify silence/mute/level behaviour and backup route.
  5. Exercise GO, pause, seek, fade, STOP ALL, blackout, remote cue, and the first/last critical cue.
  6. Verify supervisor, logs, crash-recovery checkpoint, warm-spare show/hash, and takeover interlock.
  7. Enter locked show mode; suspend packaging, indexing, updates, sync, and nonessential maintenance.

Fallback plan

Keep an independent fallback that does not share the primary machine, audio interface, display adapter, or power point where practical. Define who calls the failure, who stops/blackouts, who transfers audio/video/remote control, and how split-brain is prevented. Rehearse this with the actual operators.

Prioritised delivery roadmap

Phase 0 — Restore a trustworthy baseline

  • Land or isolate current work; require clean full test/build/vet.
  • Add Windows CI and versioned signed artifacts.
  • Capture structured logs and a visible incident surface.
  • Freeze a release test show and hardware matrix.

Phase 1 — Correct unsafe semantics

  • Reliable sequenced events and priority STOP.
  • Generation-based timer pause/seek correction.
  • Output-loss reconciliation and recovery.
  • Durable edit journal and safe save/close flow.
  • Propagate every playback/audio/remote error.

Phase 2 — Rebuild media reliability

  • Central audio mixer and ring buffers.
  • Shared timestamped A/V clock.
  • Preload/readiness, resource bounds, FFmpeg supervision.
  • Device/display notification and failover policy.
  • Move packaging away from autosave.

Phase 3 — Prove production readiness

  • Fault-injection and 24-hour soak suites.
  • Windows show-mode controls and preflight.
  • Supervisor/crash recovery and warm spare.
  • Operator runbook, training, incident drills.
  • Measured latency, sync, recovery, and capacity limits.

Release acceptance gates

A release should not be labelled theatre-ready until all of the following are evidenced on the supported Windows/hardware matrix:

  1. Clean checkout: full tests, race tests, vet/static analysis, formatting, dependency/vulnerability scan, and signed build all pass in CI.
  2. No silent drops: every command is sequenced, applied/failed, acknowledged, and recoverable after output restart.
  3. Pause, resume, seek, fade, end, links, Stop All, and timecode pass deterministic fake-clock tests and real-media tests.
  4. Audio callback meets real-time rules; supported cue/output load produces zero underruns for the soak duration.
  5. Unplug/replug of every supported audio route and display follows the documented, tested policy with a visible incident.
  6. Decoder failure, corrupt media, missing media, remote outage, disk full, file lock, sleep/resume, and process crash all fail safely.
  7. Every acknowledged edit survives crash/power interruption; every archive is verified before replacing the live document.
  8. Preflight validates the exact show/hardware state and blocks critical defects; overrides are explicit and logged.
  9. Capacity limits (cues, outputs, resolution, concurrent streams, markers, runtime) are measured, documented, and enforced.
  10. A warm-spare handoff and operator incident drill succeed using the actual production system.
Recommended immediate focus: R-01 event delivery, R-02 timer correctness, R-03/R-04 audio architecture and recovery, R-05 output reconciliation, R-06 operator-visible failures, and R-07 durable show state. These changes remove the largest “looks active but is not actually safe” failure modes.
